## Lições

- **JSON com UTF-8 em PowerShell 5.1 é frágil** (Zod recebe "object" no lugar de string). Solução: gerar payload com Python (`ensure_ascii=False`) e POST via `curl --data-binary "@file.json"` com `Content-Type: application/json; charset=utf-8`. Estável para descrições longas com acentuação.
- **Criar issue com `assigneeAgentId` definido E `status=todo` dispara wake automático no destinatário.** Verificado: EJUA-26 ficou `in_progress` por conta própria sem eu precisar disparar trigger.
- **Cadeia sequencial de blockers** (`blockedByIssueIds`) propaga `issue_blockers_resolved` em cascata. Não precisa orquestrador rodando entre etapas.
- **`issue_children_completed` é o wake natural para o pai** quando todas as filhas terminam. Combinado com `blocked + blockedByIssueIds` fica robusto e auditável.
- **Output PowerShell/Bash às vezes mostra caracteres mangled** (acentos como `�`). Os dados gravados no servidor estão corretos (UTF-8) — é só renderização do terminal local.
- **DUPLICATA DE CADEIA observada:** quando criei EJUA-19 (na verdade, quando o board criou EJUA-19 e me delegou), uma run paralela já começou a criar Cadeia A (EJUA-20–25) antes que eu lesse o contexto. Resultado: 12 filhos em paralelo, 2 cadeias completas, retrabalho dobrado. **Próximo design pattern:** ao receber wake `issue_assigned` numa issue tipo "orquestração", checar se já existem filhas antes de criar subtarefas. Adicionado como pendente em [[ejup-sprint-00]].
- **`request_confirmation` com `wake_assignee` + `supersedeOnUserComment: true`** é o padrão certo para gate humano de pacote consolidado. Aceitação acorda; rejeição/superceder por comentário também acorda com contexto.
- **`PUT /api/issues/{id}/documents/{key}`** com `body` markdown grande (~20k chars) funciona sem problemas. O `latestRevisionId` é o que entra na `target.revisionId` da interaction de confirmação.
